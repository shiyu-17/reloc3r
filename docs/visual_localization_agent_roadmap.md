# 从 LILocBench v1 到视觉定位 Agent

目标是让系统在室内动态变化、遮挡或定位证据冲突时，自己决定继续查地图、换参考、调用更强定位工具，还是接受/延迟；每一步都须能观察结果和记录成本。

**现在**：只有 LILocBench v1 固定顺序闭环基线通过运行验收。它能使用 NetVLAD 预计算参考组、Reloc3r、可选 RoMa、候选验证和历史状态，但还没有可证明优于规则的学习决策，也没有历史图像重定位分支。

下一步按以下顺序推进：

1. **守住基线**：冻结当前动作、验证、评分口径，在完整 episode 上记录正确接受、错误接受、恢复等待和工具成本；查询 GT 与在线决策严格隔离。
2. **恢复可用的在线查地图**：将 NetVLAD 查询移到当前帧执行并计费，尽量保持 v1 的参考排名和局部参考组。先与 v1 成对复测；若下降，先分解检索召回、分组和验证，不进入训练。
3. **证明动作选择有可学收益**：在同一执行前状态上试合法动作，按 episode 隔离评估“换参考或用 RoMa”是否改变终局，以及可见特征能否预测这种差异。正确候选被拒绝和错误接受必须单列。
4. **再训练最小 Agent**：前述证据成立后，训练小型策略按共同动作协议选择下一步；在未参与调参的物理场景上与固定顺序和冻结规则按同预算比较闭环恢复、安全和成本。
5. **最后扩展 Memory/视觉输入**：只有历史图像能在无 Memory 策略失败时独立帮助重估和验证，才开放 Memory 动作；只有结构化执行前证据不足而图像有可重复增益，才考虑更强视觉策略。

当前不把旧 LILocBench 预计算标签与在线协议混合训练，也不把 RIO10 的未解决错误接受并入主线。详见[项目状态](codex_project_state.md)与[历史实验摘要](experiment_history.md)。
